## [v1.4.1] — Удобство работы и палитра действий (18.11.2026)

### Добавлено
- **Палитра действий** (`Ctrl+K` / кнопка «Действия» в шапке и футере): единый
  поиск по всем операциям, доступным текущей роли. Группы «На этой странице»,
  «Создать в другом разделе», «Пользователи», «Сотрудники», «Животные», «Техника».
- **Поиск записи внутри действия**: выбор операции вроде «Заблокировать
  пользователя» открывает второй шаг со списком логинов/ФИО и живым поиском;
  то же для сотрудников, животных и резервных копий.
- **Умные hotkeys**: `N` создаёт контекстную запись (у бригадира на «Животных» —
  новое животное; у DBA открывает палитру со «Создать: Пользователи»),
  `E` редактирует выбранную строку или ведёт в палитру, `B` сразу открывает
  блокировку пользователя с поиском по логину.
- **Справка по роли** (`?`): список горячих клавиш и доступных действий строится
  из прав роли; для DBA прямо указано, что бизнес-реестры только для чтения.

### Исправлено
- Футер: панель горячих клавиш перенесена внутрь `.content` — больше не заезжает под
  сайдбар и не обрезается; подписи стали читаемее (12px вместо 11px).
- Удалены отладочные подписи REST-путей из бокового меню.
- Кнопка «Создать» показывает конкретное действие (`+ Животные [N]`), а не
  абстрактное «Новая запись»; на страницах без создания скрывается.
- `loadGrazing()` больше не дёргает `/admin/audit-log` без права `audit:READ`
  (убраны 403 в консоли у бригадира).
- Уточнено сообщение об отказе: называются недостающее право и роль пользователя.

### Проверено в browse
- Палитра, поиск действия, второй шаг с поиском пользователя и открытие модалки
  блокировки; `N` у бригадира создаёт животное, `E` редактирует выбранную строку.
- Справка для директора и DBA; консоль без ошибок на 5 разделах под ролью бригадира.

## [v1.4.0] — Доработка ИС по заданию (18.11.2026)

Шифрование персональных данных, показатели на каждом экране, рабочие функции для всех
ролей и упрощение интерфейса. OpenAPI 1.3.0 → 1.4.0 (63 → 94 пути).

### Добавлено
- **ПДн в БД**: миграция `0008_pii_encryption.sql`, таблица `employee_pii`, `pgcrypto`;
  ключ только в `PII_KEY`, передаётся в транзакцию через `set_config('app.pii_key', …)`.
  Шифруются телефон, паспорт, адрес, СНИЛС, ИНН, счёт, экстренный контакт. В реестре —
  только `phone_mask`; расшифровка по `employee:PII` с аудитом `READ_PII`.
- **Статистика**: `server/src/stats.js`, `GET /api/v1/stats`, `/stats/:section`, плашка
  `#stat-strip` на каждой странице (только по правам роли).
- **Реестры**: фильтры по полям у заголовка (`#page-tools`), выбор «25/50/100» перенесён
  в пагинацию (`#pager-limit`), убрана глобальная плашка поиска.
- **Сотрудники**: карточка с закреплениями и учётными записями, ПДн-модалка, увольнение
  и восстановление только с причиной; увольнение закрывает закрепления и блокирует
  связанные учётные записи с отзывом сессий.
- **Животные**: статусы `НА_ПРОДАЖЕ` / `ПРОДАН`, продажа требует причины `SALE`;
  закрепление сотрудников (`/animals/:id/assignments`, `/employees/:id/assignments`),
  сводка бригадира `/animals/herd` на странице выпаса.
- **Админка**: блокировка/разблокировка с причиной, генерация временного пароля,
  просмотр и отзыв сессий, редактирование матрицы прав ролей, аудит с фильтром по
  пользователю и отбором нарушений (`category=violations`, `user_id`).
- **Резервные копии**: `/tech/backups/overview` — текущая копия, настройки периода,
  история и восстановления на одной странице; скачивание файла, плановая копия.
- **Метрики**: `server/src/perf.js`, `/tech/metrics/perf` — перцентили, корзины,
  медленные запросы, состояние БД и готовый вердикт о необходимости оптимизации.
- **Демо-данные**: миграция `0010_demo_extra.sql` (140 голов, 80 закреплений, 21 сотрудник,
  11 пользователей, 9340 задач, 29736 движений).
- `docs/ui_guide.md`, `docs/demo_scenarios.md`, обновлены `README.md`, `docs/security.md`, `docs/backup_policy.md`,
  `server/src/openapi.json`, `Приложение_А_Код.md`.

### Изменено
- Роль DBA: полные права на `user/tech/dba/backup`, бизнес-объекты — только чтение;
  проверка при `PUT /admin/roles/:id/permissions`.
- Триггер `fn_animal_close_assignments`: закрепления закрываются при выбытии животного.
- Docker: `PII_KEY`, `BACKUP_SCHEDULER`, `BACKUP_TICK_MS`, `FARM_PSQL_MODE=local`,
  `FARM_BACKUP_DIR=/app/backups`.

### Исправлено (найдено при проверке UI)
- `audit_log_action_check` не допускал `READ_PII`: чтение ПДн отдавало данные,
  но аудит молча падал. Миграция `0012_audit_read_pii.sql` расширяет CHECK;
  базовая схема `01_schema.sql` обновлена; в CHECK 19 добавлена проверка записи.
- `routes/dba.js`: неверный тип `bool` в валидации (`POST /migrations/apply`
  падал 500) — заменён на `boolean`.
- Пути в Docker: раннер миграций не видел `db/migrations`, а предмиграционный
  бэкап искал `/scripts/backup_restore.py`. Dockerfile копирует миграции,
  пути определены с учётом обоих окружений (локально и в образе).
- UI: `panel()` падала на `null` в списке действий (страница «Выпас» и
  «Скорость БД» для ролей без `tech:EXEC`); снят лишний запрос
  `/grazing/active` (эндпоинта нет — 404 в консоли).

### Проверено
- `db/99_checks.sql` — **22/22**; 12 миграций применены, контрольные суммы совпадают.
- Живой API: все `/stats/*`, `/employees` (ПДн, увольнение), `/animals/herd`, блокировки,
  пароли, сессии, права ролей, аудит `violations`, реальный `pg_dump` + скачивание,
  плановая копия, `/tech/metrics/perf` (вердикт OK, p95 ≈ 57 мс).
- `node --check ui/public/app.js` — синтаксис корректен; UI готов к проверке в браузере.
