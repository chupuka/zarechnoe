# Демонстрационные сценарии (вариант 11, v1.4.0)

Стенд: `docker compose up -d` → UI <http://localhost:3000/app/>, API
<http://localhost:3000/api/v1>, Swagger <http://localhost:3000/api/v1/docs>.
Пароль всех демо-пользователей — `demo1234`.

> Технические роли (`superuser`, `dba`) при каждой записи передают заголовок
> `X-Override-Reason` **только ASCII** (кириллица в заголовке ломает Node.js).
> Пример: `X-Override-Reason: Demo check of PII encryption`.

## 1. Шифрование ПДн (директор)

1. Войти `director`. На «Главной» — показатели поголовья, задач, бэкапов.
2. «Сотрудники» → в реестре только `phone_mask` и признак ПДн.
3. Кнопка строки **«ПДн»** → полные поля. Внизу модалки — предупреждение,
   что чтение пишется в аудит.
4. «Журнал аудита» → `Категория: Просмотр ПДн` → найти событие `READ_PII`
   с логином `director`.

Проверка «напрямую в БД» (доказательство шифрования):

```bash
docker exec farm_pg psql -U farm -d farm -c \
  "SELECT employee_id, left(phone,24) AS phone_cipher, key_version FROM employee_pii LIMIT 3;"
# открытого телефона нет; расшифровка возможна только с PII_KEY
```

Попытка обойти функцию шифрования (`99_checks.sql`, CHECK 18) приводит к
`Wrong key or corrupt data`. Ключ `PII_KEY` в БД и в репозитории отсутствует.

## 2. Статистика на каждой странице

Войти под разными ролями и сравнить плашку:

| Логин | Что видно в плашке |
|---|---|
| `director` | поголовье, требующие внимания, на продаже, задачи, остатки, бэкапы, отказы |
| `foreman` | показатели выпаса и задач (без пользователей и аудита) |
| `storekeeper` | остатки, позиции ниже минимума, движение склада |
| `dba` | только технические показатели и статистика пользователей/бэкапов |

Плашка, к которой у роли нет права, не отображается вовсе (403 на `/stats/:section`).

## 3. Бригадир: выпас и закрепления

1. Войти `foreman` → «Операции → Выпас».
2. Сверху — сводка: число закреплений, покрытых животных, список «Без закрепления».
3. Кнопка **«Закрепить сотрудника»** → выбрать сотрудника, животное, роль
   (`VET`/`HERDSMAN`/`FOREMAN`/`ZOOTECHNIK`).
4. «Животные» → кнопка строки «Закрепить» назначает того же сотрудника на конкретную голову.
5. Сменить статус животного на `ПРОДАН` с причиной `SALE` → закрепления закроются
   автоматически (триггер `fn_animal_close_assignments`).

## 4. Продажа и выбытие

```
POST /api/v1/animals/62/status
{ "status": "ПРОДАН", "reason": "Реализация по договору №12", "disposal_reason_id": <SALE> }
```

После ответа: `GET /animals/62/assignments` → активных нет; карточка показывает
новый статус; событие есть в аудите.

## 5. Админка пользователей и аудит

1. Войти `director` → «Пользователи».
2. `temp.operator` уже заблокирован с причиной — фильтр `Состояние: Заблокированы`.
3. Кнопка **«Разблокировать»** (причина обязательна) → пользователь снова активен.
4. **«Новый пароль»** → временный пароль показывается один раз, при входе
   требуется смена (`must_change_pw`).
5. **«Сессии»** → список активных сессий → «Отозвать все сессии».
6. «Роли и права» → «Права роли» → снять/поставить право и сохранить. Попытка
   дать DBA запись в бизнес-объект вернёт 400.
7. «Журнал аудита» → `Пользователь: <логин>` + `Отбор: Только нарушения (DENY)`
   или `Действие: DENY`. Кнопка CSV выгружает тот же отбор.

## 6. Бэкапы на одной странице (dba)

1. Войти `dba` → «Резервные копии».
2. Блок «Текущая копия»: последний успешный дамп, размер, контрольная сумма,
   инициатор. Кнопка «Скачать файл» — реальный `octet-stream`.
3. «Период копирования»: частота, время, срок хранения, число копий. Сохранить —
   `PATCH /tech/backups/schedule`; «Выполнить план сейчас» —
   `POST /tech/backups/schedule/run`.
4. «История копий» и «Восстановления» — на той же странице, без поиска.
5. Восстановление (`POST /tech/restores`) — обязательны причина и право
   `backup:EXEC`; после него проверить `v_stock_balance_check` (0 расхождений).

## 7. Скорость БД

1. Войти `dba` → «Скорость БД».
2. Зелёный вердикт «БД отвечает быстро» + p95 (на демо-стенде ≈ 57 мс).
3. Если p95 выше порога — вердикт меняется, в таблице «Самые медленные запросы»
   видны SQL-шаблоны, а в «Состоянии базы» — таблицы с большим seq scan.
4. Пороги правятся в `farm_settings` (`perf_p95_ok_ms`, `perf_p95_warn_ms`,
   `perf_slow_ms`) без пересборки. Кнопка «Сбросить статистику» очищает окно.

## 8. Фильтры и пагинация (любая роль)

- Глобального поиска нет: у «Животных» — статус, группа, закрепление;
  у «Сотрудников» — должность, работает, ПДн, закрепления, удалённые;
  в аудите — пользователь, действие, категория, даты.
- «Сбросить» возвращает состояние раздела. Выбор «50/100» живёт в нижней
  пагинации и сохраняется при перелистывании.

## 9. Итоговая проверка

```bash
docker cp db/99_checks.sql farm_pg:/tmp/99_checks.sql
docker exec farm_pg psql -U farm -d farm -v ON_ERROR_STOP=1 -f /tmp/99_checks.sql
# ожидается: === ВСЕ 22 ПРОВЕРОК ПРОЙДЕНЫ ===
```
